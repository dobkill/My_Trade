# 一、先确定整个系统的思想

我建议不要做：

**数据 → 一个大模型 → 买/卖**

而做：

**数据 → 多个职责不同的模型 → 概率融合 → 风险过滤 → 交易决策**

大概是：

```text
股票历史数据
     ↓
特征工程
     ↓
┌─────────────────────┐
│ ① 市场状态模型       │
│ ② 涨跌概率模型       │
│ ③ 未来收益模型       │
│ ④ 风险/回撤模型      │
│ ⑤ 模型融合/决策模型  │
└─────────────────────┘
     ↓
数学交易规则
     ↓
买入 / 卖出 / 不交易
     ↓
仓位大小
```

我建议**第一版控制在 4～5 个模型职责**，不要一开始搞十几个模型。

---

# 二、设计成这 5 个模型

| 模型   | 职责          | 推荐方法                           | 输出                | 模型回答的问题               |
| ---- | ----------- | ------------------------------ | ----------------- | --------------------- |
| 模型 A | 判断市场环境      | HMM / GBDT / 固定规则              | 趋势/震荡/高波动         | **现在是什么行情？**          |
| 模型 B | 预测未来 10 日方向 | LightGBM / XGBoost             | P涨、P跌、P横盘         | **未来 10 天更可能涨还是跌？**   |
| 模型 C | 预测未来收益分布    | Quantile GBDT                  | 10日收益 P10/P50/P90 | **如果涨/跌，大概能涨跌多少？**    |
| 模型 D | 预测风险        | LightGBM / Quantile Regression | 波动率、最大回撤风险        | **中间最坏可能亏多少？**        |
| 模型 E | 最终融合        | Logistic / 简单规则 / 小型GBDT       | 买/卖/未知            | **综合前面结果，这笔交易到底做不做？** |

其中你说的“走势图通道模型”，**我不建议一开始使用机器学习**。

直接使用数学模型往往更好：

```text
线性回归通道
ATR 通道
Donchian Channel
Bollinger Band
滚动高低点
Kalman Filter 趋势
```

机器学习应该负责解决**概率问题**，不必让 AI 做本来一个公式就能稳定解决的问题。

# 三、最重要的模型：未来 10 天方向模型

不要让模型只输出：
```text
上涨
下跌
未知
```
模型内部最好输出：
```text
P(上涨) = 0.67
P(横盘) = 0.20
P(下跌) = 0.13
```

XGBoost 等分类模型本身就可以输出多分类概率；如果系统最终要依赖“67%”这种数字做仓位和交易判断，就还应专门做**概率校准**。scikit-learn 也专门提供了概率校准方法，并强调校准数据应该与模型拟合数据分离。([XGBoost 文档](https://xgboost.readthedocs.io/en/release_3.2.0/parameter.html?utm_source=chatgpt.com "XGBoost Parameters — xgboost 3.2.1 documentation"))

然后**交易系统**再决定：

```text
上涨概率高 → 上涨
下跌概率高 → 下跌
没有明显优势 → 未知
```

这里有一个很重要的区别：

**“横盘”是市场状态。**

**“未知”是模型不确定。**

这两个概念最好不要混在一起。

例如：

```text
P上涨 36%
P横盘 31%
P下跌 33%
```

这不是“预测横盘”。

而是：

> 模型根本不知道。

因此最终应该：

```text
UNKNOWN
禁止交易
```

这实际上就是机器学习里的 **abstention / reject option（拒绝预测）** 思想。

# 四、未来 10 天不要只预测第 10 天价格
假设两种情况：
### 股票 A

```text
第1天 +2%
第2天 +4%
第3天 +6%
第5天 +8%
第10天 +10%
```

### 股票 B

```text
第1天 -8%
第3天 -12%
第5天 -5%
第10天 +10%
```

最终都是：

```text
10日收益 +10%
```

但显然不是一种交易。

所以模型应该同时预测：

```text
未来1日收益
未来3日收益
未来5日收益
未来10日收益

未来10日最大上涨 MFE
未来10日最大下跌 MAE
未来10日波动率
```

多周期预测本身也是成熟的时间序列建模方向；例如 TFT 就专门针对 multi-horizon forecasting，但以你目前“每只股票独立 + 5 年日线”的数据量，我不会第一版就上 TFT/Transformer。([arXiv](https://arxiv.org/abs/1912.09363?utm_source=chatgpt.com "Temporal Fusion Transformers for Interpretable Multi-horizon Time Series Forecasting"))

# 五、模型 C：不要预测一个价格，而是预测“收益概率区间”

这是非常重要的一层。

例如模型输出：

```text
未来10日收益：

P10 = -4.2%
P25 = -1.1%
P50 = +3.4%
P75 = +7.2%
P90 = +11.5%
```

这比：

> AI 预测未来上涨 5.3%

有价值太多。

你真正想知道的是：

> 收益分布长什么样？

这种模型可以直接用 **Quantile Regression（分位数回归）**。目前 scikit-learn 的梯度提升回归器以及 LightGBM 都支持 quantile 类型目标。([Scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html?utm_source=chatgpt.com "HistGradientBoostingRegressor — scikit-learn 1.9.0 documentation"))

于是可能出现：

股票甲：

```text
预测收益中位数     +5%
坏情况 P10        -2%
```

股票乙：

```text
预测收益中位数     +7%
坏情况 P10        -15%
```

虽然乙预测收益更高，我反而可能选择甲。

这才真正开始接近**概率交易**。

# 六、模型 D：风险预测模型

这一点很多量化系统会忽略。

不要只预测：

> 能涨多少？

还应该预测：

> 错了会亏多少？

模型 D 可以专门预测：

```text
未来10日波动率

未来10日：
最大潜在回撤 MAE

P(回撤 > 3%)
P(回撤 > 5%)
P(回撤 > 10%)
```

例如：

```text
方向模型
上涨概率：74%

收益模型
P50：+6.1%

但是：

风险模型
P(10日内回撤 > 8%) = 46%
```

那么系统依然可以拒绝这笔交易。

这就是：

**预测模型负责找机会。**

**风险模型负责否决机会。**

可以划成例如：

```text

```

即使坚持：

> 每只股票模型单独训练

也完全可以让这只股票的模型读取：

```text

行业指数
VIX类波动指标
利率

```

**“独立训练”并不等于“只能使用自己股票的数据”。**

这一点我建议坚持。

# 十一、标签怎么定义，我建议这样做

不要直接：

```python
未来价格 > 今天价格:
    上涨
else:
    下跌
```

因为：

```text
+0.1%
```

没有任何交易意义。

应该设一个**动态阈值**。

例如：

[  
R_{10} = \frac{Close_{t+10}}{Close_t}-1  
]

阈值根据股票当前波动率决定：

[  
Threshold = k \times \sigma_{20} \times \sqrt{10}  
]

然后：

```text
R10 > Threshold
→ UP

R10 < -Threshold
→ DOWN

否则
→ NEUTRAL
```

这样：

高波动股票可能需要：

```text
+5%
```

才算真正上涨。

低波动股票可能：

```text
+2%
```

就已经非常显著。

这个 `k` 不应该凭感觉决定，而是在历史 walk-forward 验证里选择。

# 十二、训练方法甚至比模型本身更重要

**绝对不要随机打乱数据然后做普通 KFold。**

时间序列必须保持时间顺序，否则容易出现“拿未来训练过去”的问题。scikit-learn 的 `TimeSeriesSplit` 就是专门为时间顺序数据准备的，而且提供 `gap` 参数，在训练和测试之间留隔离区。([Scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html?utm_source=chatgpt.com "TimeSeriesSplit — scikit-learn 1.9.0 documentation"))

因为你的预测周期是 **10 个交易日**，我会在训练/验证边界上专门留出至少与标签窗口匹配的隔离区域，以避免 10 日标签跨越训练和测试边界；这是基于你的标签设计做出的防泄漏措施。([Scikit-learn](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html?utm_source=chatgpt.com "TimeSeriesSplit — scikit-learn 1.9.0 documentation"))

例如做：

```text
2019 ───── 2022 | GAP | 2023Q1
     Training           Validation

2019 ───── 2023Q1 | GAP | 2023Q2
       Training              Validation

2019 ───── 2023Q2 | GAP | 2023Q3
          Training               Validation
```

也就是：

**Walk Forward Validation。**

而不是：

```text
随机80%训练
随机20%测试
```

# 十四、最终交易逻辑才是整个软件真正的大脑

不要写：

```text
if model == UP:
    buy()
```

我会设计成类似：

```text
方向模型：
P上涨 = 0.71
P横盘 = 0.17
P下跌 = 0.12

收益模型：
10日 P50 = +5.8%
10日 P10 = -2.4%

风险模型：
未来10日波动 = 3.1%
严重回撤概率 = 8%

市场模型：
正常上涨趋势

模型一致性：
82%
```

系统才判断：

```text
P上涨 > 最低要求
AND
预期收益 > 交易成本 + 安全边际
AND
风险 < 最大允许风险
AND
市场环境允许
AND
模型之间没有明显冲突

→ BUY
```

否则：

```text
UNKNOWN / NO TRADE
```

例如你最终可能让系统一天扫描 500 只股票：

```text
强烈上涨       7
上涨           19
未知           438
下跌           28
强烈下跌       8
```

**438 个未知完全没有问题。**

如果数学优势不存在：

> 不交易本身就是交易策略的一部分。

# 十五、仓位也应该数学化

这是你“彻底剔除个人因素”的另一半。

不应该：

> 这个股票感觉特别好，多买一点。

而应该：

[  
Position =  
f(  
Edge,  
Confidence,  
Volatility,  
DrawdownRisk  
)  
]

例如一个简化版本：

[  
Edge=P(up)-P(down)  
]

然后：

[  
PositionSize  
\propto  
\frac{Edge}{PredictedVolatility}  
]

再加硬限制：

```text
单股票最大仓位
行业最大仓位
组合最大风险
单日最大亏损
最大组合回撤
```

也就是说：

**模型决定机会。**

**风险系统决定你能押多少钱。**

这两个必须分开。

# 十六、还有一个我非常建议加入的东西：模型分歧

假设三个方向预测器：

```text
Logistic        P上涨 58%
LightGBM        P上涨 79%
XGBoost         P上涨 55%
```

虽然平均：

```text
64%
```

但模型明显存在分歧。

那么系统应该降低置信度。

反过来：

```text
Logistic        70%
LightGBM        73%
XGBoost         71%
```

这个信号明显更可靠。

所以你可以计算：

```text
ensemble_mean
ensemble_std
```

把模型间标准差作为一个风险指标。

# 十八、为什么我一定会保留 Logistic Regression

你可能会觉得：

> 都 AI 时代了，为什么还用逻辑回归？

因为它是非常好的**基准模型**。

假如：

```text
Logistic
测试收益不错

LightGBM
稍微好一点

Transformer
回测超级好
实盘验证很差
```

你马上就能发现：

> 复杂模型可能只是过拟合。

金融模型最大的问题之一就是回测过拟合，而不是模型“不够复杂”。相关研究也专门讨论了金融策略在参数和回测过程中产生过拟合的问题。([arXiv](https://arxiv.org/abs/1905.05023?utm_source=chatgpt.com "Avoiding Backtesting Overfitting by Covariance-Penalties: an empirical investigation of the ordinary and total least squares cases"))

# 十九、评价模型千万不要主要看 Accuracy

比如：

```text
上涨预测准确率：61%
```

几乎没有办法直接说明策略好不好。

你真正需要维护两套指标。

**模型指标：**

```text
Log Loss
Brier Score
Probability Calibration
Precision-UP
Precision-DOWN
Recall
UNKNOWN Coverage
```

尤其你的系统依赖概率，因此概率是否校准比单纯分类正确率重要得多。一个经过良好校准的分类器，其预测概率才更接近可以解释成真实置信水平的数值。([Scikit-learn](https://scikit-learn.org/stable/modules/calibration.html?utm_source=chatgpt.com "1.16. Probability calibration — scikit-learn 1.9.0 documentation"))

然后看**策略指标**：

```text
净收益
年化收益
最大回撤
Sharpe
胜率
盈亏比
Profit Factor
平均单笔收益
交易频率
持仓周期
手续费后收益
滑点后收益
```

模型最终的目标不是：

> Accuracy 最高。

而是：

> **样本外、扣除成本后，风险调整收益最好。**

# 最终我建议的整体架构

你的系统最终可以分成 **7 层**：

```text
第一层
```

所以我认为，你这个项目真正应该追求的不是：

**“训练一个非常准的股票 AI。”**

而应该追求：

> **建立一套由多个弱预测器、风险模型和数学规则组成的决策机器；模型允许犯错，但系统只在预测优势足够大、风险足够小的时候下注。**

如果是我来做，**下一步最值得先确定的不是代码，而是“训练标签体系”**。也就是把 `未来1/3/5/10日收益、上涨/横盘/下跌、MFE、MAE、波动率` 的数学定义全部确定下来。一旦标签设计正确，后面的特征、模型、训练和回测架构都会清晰很多。
